3. 合并原则

课程不是机械按 3 个知识点一组。只有当几个知识点属于同一机制、同一状态机、同一数据流或天然需要一起解释时才合并。像 CanTp 的 FC / BS / STmin / N_xx timeout 会放在同一课；而足够大的综合 Debug 或公司岗位映射允许单独成课。

A. 上课阶段

A1｜先建立心智模型

先讲它解决什么问题、位于哪一层、上下游是谁、为什么需要这一机制；不要一上来堆配置字段。

A2｜一节课覆盖全部挂载的 Z 知识点

课程编号是组织单位，但课程卡片下列出的每一个 Z 知识点都必须真正讲到，不能因为合并而漏项。相反，合并是为了把因果关系讲得更完整。

A3｜运行时链路 / 状态机 / 时序优先

必须把数据流、调用链、状态转换条件或时序串起来。适合画图的内容课堂先用简图，打印笔记优先改成 SVG。

A4｜配置必须落到 Runtime 行为

讲 AUTOSAR 标准概念后，再对应 EB tresos / DaVinci。厂商字段名只有确认过才写；无法确认必须标“版本/供应商相关”。

A5｜API / Callback / MainFunction

涉及接口时讲清“谁调用谁、什么时候调用、参数代表什么、异常时会怎样”，但不为显得深入而贴无意义的大段源码。

A6｜Debug 是 P0/L3 的硬要求

至少给出一个完整“现象 → 假设 → 观测点 → 证据 → 根因 → 修复 → 回归”。通信、诊断等主航道课程尽量给 2～3 个。

A7｜面试追问树

至少 3 层：定义 → 机制/配置 → 项目/异常；P0/L3 尽量达到 4～5 层，并指出哪些回答会暴露“只会配不会原理”。

A8｜小测闭环

课程结束用 3～8 题确认理解，概念题和场景题混合。错误先纠正，再进入下一课。
