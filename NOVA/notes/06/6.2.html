11. CanIf 配置项

11. CanIf 配置项

CanIf 是 CAN Interface。它在 CanNm/CanTp/Com 等上层模块和 CAN Driver 之间，负责 PDU 到 CAN 硬件对象的映射。

CanNm / CanTp / Com
    -> CanIf PDU
        -> HTH / HRH
            -> CAN Driver / Controller
CanNm 决定何时发 NM。
CanIf 决定这帧 NM 用哪个 CAN ID、走哪个 HTH、从哪个 HRH 收、回调给谁

如果收不到 NM：

1. CAN ID 是否落在 CanIfRxPduCanIdRangeLowerCanId / CanIfRxPduCanIdRangeUpperCanId 区间内。
2. CanIfRxPduTargetPduID 是否对到目标 Rx PDU。
3. CanIfRxPduUpperLayerRef 是否指向 CanNm。
4. DLC 是否符合预期。
5. CanNmRxPduRef 是否引用这个 Rx PDU。
6. 是否调用到 CanNm_RxIndication。

如果发不出 NM：

1. ComM 是否 FullCom。
2. CanSM Controller 是否 STARTED。
3. CanNm 是否到了发送状态。
4. TxPduId / CanNmTxPduRef(EB) 是否引用正确 Tx PDU。
5. CanIf Tx PDU 是否 ONLINE。
6. HTH 是否绑定正确 Controller。
7. Tx buffer 是否满。
8. 是否有 TxConfirmation。

11.3 CANIF_RANGE_RECEPTION / CanIfPublicRangeReceptionSupport(EB)

EB 区间接收对象：CanIfRxPduCanIdRange
EB 实际字段：CanIfRxPduCanIdRangeLowerCanId / CanIfRxPduCanIdRangeUpperCanId / CanIfRxPduTargetPduID / CanIfRxPduUpperLayerRef

当前：true

含义：CanIf 支持范围接收。

影响：可以用一个范围匹配一组 CAN ID。但范围、HRH、上层 PDU 引用必须准确。

风险：范围太宽:可能误收不该给 CanNm 的报文。范围太窄:对端 NM ID 可能收不到。

11.4 CANIF_PUBLIC_TX_BUFFERING / CanIfPublicTxBuffering(EB)

当前：true

含义：CanIf 支持 Tx buffering。

影响：短时间发送拥塞时，CanIf 可以缓存待发 PDU。但 buffer 不足时仍可能发送失败或延迟。

偶发 NM 发不出或 TxConfirmation 超时：查 Tx buffer 配置。查 HTH 是否拥塞。查总线负载。

11.5 CANIF_DLC_CHECK_ENABLED / CanIfPrivateDlcCheck(EB)

当前：false

含义：CanIf 不做严格 DLC 检查。

影响：DLC 不匹配的问题可能不会在 CanIf 层被挡住。错误可能到 CanNm/CanTp/上层才表现出来。

11.6 CanIf PN / Wakeup 开关

当前：

CANIF_PUBLIC_PN_SUPPORT / CanIfPublicPnSupport(EB) = false
PublicCtrlWakeupSupport / CanIfPublicCtrlWakeupSupport(EB) = false
CANIF_CANTRCV_WAKEUP_SUPPORT / CanIfPublicTrcvWakeupSupport(EB) = false
CANIF_WAKEUP_CHECK_VALID_BY_NM / CanIfPublicWakeupCheckValidByNM(EB) = true

含义：

当前 CanIf 不启用 PN 过滤支持。 当前也不通过 CanIf 控制器/收发器唤醒路径。
虽然 WakeupCheckValidByNM = true，但相关硬件唤醒和 CarWakeUp 链路没有完整打开。

诊断帧物理唤醒：

不要只看 CANIF_WAKEUP_CHECK_VALID_BY_NM / CanIfPublicWakeupCheckValidByNM(EB)。
如果 Controller/Trcv wakeup support 关闭，且硬件按任意 CAN 活动唤醒，
软件层未必能阻止第一次唤醒。

11.7 CanIf 常见故障定位

收不到 NM：

1. 对端 CAN ID 是否落在 CanIfRxPduCanIdRangeLowerCanId / CanIfRxPduCanIdRangeUpperCanId 区间内。
2. CanIfRxPduTargetPduID 是否对到目标 Rx PDU。
3. CanIfRxPduUpperLayerRef 是否指向 CanNm。
4. Driver filter / Controller 接收路径是否放行。
5. CanNmRxPduRef 是否对上。
6. 是否进入 CanNm_RxIndication。

发不出 NM：

1. TxPduId / CanNmTxPduRef(EB) 是否对上 CanIf Tx PDU。
2. HTH 是否对应正确 Controller。
3. CanSM 是否 STARTED。
4. PDU mode 是否 ONLINE。
5. Tx buffer 是否足够。
6. CanNm_TxConfirmation 是否回来。

诊断不通：

1. 诊断 Rx/Tx PDU 是否配置在 CanIf。
2. Upper Layer 是否 CanTp。
3. CanTp/PduR/DCM 路由是否正确。
4. Controller 是否 STARTED。
5. PDU mode 是否 ONLINE。

11.8 CanIf 章节口诀

CanIf 是 PDU 到 CAN 硬件对象的桥。
CAN ID、DLC、HRH、HTH、Upper Layer 都在这里决定。
RxPduId / CanNmRxPduRef(EB) / TxPduId / CanNmTxPduRef(EB) 必须和 CanIf PDU 对齐。
收不到先查 Rx ID/HRH/UL/RxIndication。
发不出先查 Tx PDU/HTH/PDU mode/TxConfirmation。
