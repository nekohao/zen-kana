0. 30 秒脑内模型

CanTp
完整数据太大时负责拆成多个 CAN N-PDU发送；接收时再拼回一个完整 N-SDU。
层级
DCM ↔ PduR ↔ CanTp ↔ CanIf ↔ CAN Driver
N-SDU
上层眼中的完整一包 TP 数据，例如整个诊断 Request / Response。
N-PDU
CanTp 与 CanIf 之间一帧一帧传输的 PDU，例如承载 SF/FF/CF/FC 的底层帧。
RxNSdu
本 ECU 收 DATA + 发 FC。
TxNSdu
本 ECU 发 DATA + 收 FC。
最重要条件反射：RxNSdu = 收 DATA + 发 FC；TxNSdu = 发 DATA + 收 FC。

1. 四种 CanTp 帧

PCI帧一句话最常见格式
0xSF数据一帧装完。0X ...；Classic CAN 常见 X=有效数据长度。
1xFF第一帧，告诉对方后面还有，同时带整个 N-SDU 总长度。10 LL ...
2xCF后续数据帧；低 4 bit 是 SN。21,22,...,2F,20,21...
3xFCReceiver 控制 Sender 后续 CF 怎么发。30/31/32 BS STmin
SF 示例
03 22 F1 90 00 00 00 00
03：SF，长度=3
真正 UDS：22 F1 90
后面的 00：Padding
FF 示例
10 24 62 F1 90 ...
0x024 = 36 Byte
36 是整个 N-SDU 总长度，不是本帧长度。

FC：30 / 31 / 32

值含义人话
30 / CTSContinue To Send继续发。
31 / WAITWait先等等，我还没准备好。
32 / OVFLWOverflow接收不了，本次传输失败。不是正常结束。

BS / STmin / SN

概念一句话例子
BSReceiver 允许 Sender 连续发多少个 CF。BS=8：8 个 CF 后重新等 FC；BS=0：剩余 CF 可一直发完，不再因 BS 等新 FC。
STminReceiver 要求 Sender 的相邻 CF 最小间隔。00~7F=0~127 ms；F1~F9=100~900 μs。
SNCF 的 Sequence Number，低 4 bit；必须连续。21→22→...→2F→20→21。
BS/STmin 到底谁决定？
我的 ECU 接收多帧 → BS/STmin 由我的 RxNSdu 配置决定，我通过 FC 告诉对方。
我的 ECU 发送多帧 → BS/STmin 由对方 FC 决定，我照着执行。
CanTpChangeParameterApi=OFF 时按 EB 固定配置理解；开启后可通过标准 API 在运行时修改 Rx 侧 BS/STmin。

11. CAN FD 下的 CanTp

Classic CANCAN FD
Payload 最大 8 Byte。Payload 最大 64 Byte。
Normal Addressing 下常见 SF：0X，X 可直接表示较短 SF 长度。较长 SF 可用扩展 SF_DL；不能机械认为低 4 bit 永远是完整长度。
大数据需要 FF/FC/CF。一帧能装更多，但超过单帧能力仍然 FF/FC/CF。
CAN FD 扩展 SF_DL 示例：
00 14 62 F1 90 ...
00：SF 的扩展长度形式
0x14：20 Byte 的 SF_DL
→ 不要看到 00 就误判成“长度为0”。
CAN FD 只是“每个 N-PDU 能装更多”；SF / FF / FC / CF、BS、STmin、SN、Timer 的核心思想都没变。

当前项目 CanTpFlexibleDataRateSupport = ON，表示 CanTp 具备 CAN FD 支持；具体某条 DIAG PDU 是否走 FD，还要看 CanIf / CAN Controller / PDU 配置。

易混淆速查

  1. N-SDU 是整个数据；N-PDU 是一帧一帧的数据。
  2. FF 中长度是整个 N-SDU 总长度，不是 FF 本帧长度。
