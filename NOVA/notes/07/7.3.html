2. Physical / Functional 与 Addressing

TaType：找谁？
PHYSICAL：找某一台 ECU。
FUNCTIONAL：1:n，一次请求给一类 ECU。
AddressingFormat：地址放哪里？
STANDARD / EXTENDED / MIXED / NORMAL FIXED 决定地址信息放在 CAN ID 还是 Payload，以及 PCI 从哪个 Byte 开始。
不要混：Physical/Functional = 找谁；AddressingFormat = 地址信息放哪里。

Functional Request 只走 SF。若功能请求触发的 Response 很大，ECU 通过 Physical TxNSdu 进行多帧响应。

Tester → 多个 ECU：Functional SF Request
某 ECU 需要返回很多数据
ECU → Tester：Physical FF
Tester → ECU：Physical FC
ECU → Tester：Physical CF / CF ...
Addressing人话PCI 开始位置
STANDARD / NormalCAN ID 已足够区分通信对象，Payload 不再额外放地址。Byte0
EXTENDEDCAN ID 还不够，所以 Payload 前再放 1 Byte 地址。Byte1；Byte0 是地址
MIXEDCAN ID + Payload 中 Address Extension 一起决定通信关系。Byte1
NORMAL FIXED固定格式 29-bit CAN ID 中编码源/目标地址。通常 Byte0

易混淆速查

  1. TaType 决定 Physical/Functional；AddressingFormat 决定地址放在哪里。
  2. Functional Request 只用 SF；需要多帧的 Response 走 Physical Tx。
