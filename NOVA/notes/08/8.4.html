B.1 先分清四种“唤醒”

类型含义主查模块典型误区
物理唤醒ECU 从低功耗被总线/引脚/Transceiver 唤醒。EcuM、CanTrcv、MCU Wake Source、CanIf Wakeup软件 DCM/ComM/CanNm 通常挡不住第一次物理唤醒。
逻辑通信唤醒系统已经醒来后，请求某通信通道进入 FullCom。ComM、BswM、CanSM这不是硬件唤醒，而是通信模式请求。
NM Active WakeupNM CBV 里的 Active Wakeup bit，表示本节点主动唤醒网络。CanNm CBV / ActiveWakeup 配置不要和 CarWakeUp bit 混为一谈。
CarWakeUpNM PDU 里客户定义的 Car WakeUp 语义 bit，被 CanNm/Nm 解析后上报。CanNm、Nm、BswM/EcuM当前 DF_XY 关闭，byte/bit 有值也不触发语义。
Selective Wake / PN WakeTransceiver/Controller 根据特定 ID/Pattern/PN 决定是否唤醒。CanTrcv、CanIf、CanSM、EcuM、PNC它可以和 PNC 联动，但不是普通 PNC 配置本身。

B.2 ComM 逻辑通信唤醒链路

App / DCM / BswM 请求通信
    -> ComM_RequestComMode(User, COMM_FULL_COMMUNICATION)
        -> ComM 检查 NoCom / NoWakeup / CommunicationAllowed / Inhibition
            -> CanSM_RequestComMode(Network, FULL)
                -> CanIf / CanDrv / CanTrcv 拉起 Controller / Transceiver
                    -> Nm_NetworkRequest / CanNm_NetworkRequest
                        -> NM 报文保持网络

B.3 硬件唤醒链路

总线活动 / Wake Pattern / Transceiver Wake
    -> CanTrcv / CAN Controller / MCU Wake Source
        -> EcuM_CheckWakeup / EcuM_SetWakeupEvent
            -> BswM / EcuM 唤醒处理
                -> ComM_CommunicationAllowed / ComM_RequestComMode
                    -> CanSM 拉起 Controller
配置点作用排查
EcuM Wake Source定义哪些硬件源可以唤醒 ECU。物理能醒但软件无反应，查 EcuM wake source / validation。
CanTrcv Wakeup / Selective WakeTransceiver 层的唤醒/选择性唤醒能力。只有特定 ID/Pattern 能唤醒时重点查这里。
CanIf Wakeup SupportCanIf 向上报告 Controller/Transceiver wakeup。底层有 wake，但上层不知道时查 CanIf/EcuM 回调。
BswM wake rules唤醒后决定是否允许通信、是否请求 FullCom。物理醒了但 CAN 不通信，查 BswM/ComM 逻辑。

B.4 CarWakeUp 配置链路

模块关键配置作用
CanNmCanNmCarWakeUpRxEnabled、CarWakeUp Byte/Bit决定是否解析收到 NM PDU 里的 CarWakeUp bit。
NmNmCarWakeUpRxEnabled决定 Nm 抽象层是否接收/上报 CarWakeUp 语义。
BswM/EcuMCarWakeUp 相关 rule / wake source决定收到 CarWakeUp 后系统行为。
CanIfRx PDU / HRH / Range / DLCNM PDU 必须先能被 CanIf 收到并上送 CanNm。

B.5 Active Wakeup Bit 不是 CarWakeUp

项目Active WakeupCarWakeUp
位置通常在 CBV bit4客户定义的 NM PDU byte/bit
语义本节点主动唤醒网络的标识车辆唤醒/整车唤醒语义
主配置CanNm ActiveWakeup 相关配置CanNmCarWakeUpRxEnabled / NmCarWakeUpRxEnabled
当前 DF_XY看 CBV/CanNm 配置是否使用关闭，不解析

B.6 唤醒问题排查口诀

先问“有没有物理醒”：
    没醒 -> 查 CanTrcv / Wake Source / Selective Wake / 供电。
再问“醒了有没有允许通信”：
    醒了但不通信 -> 查 EcuM / BswM / ComM_CommunicationAllowed / ComM_RequestComMode。
再问“Controller 有没有起来”：
    ComM 请求了但 Controller 不起 -> 查 CanSM / CanIf / CanDrv / mode indication。
最后问“NM 有没有保持网络”：
    Controller 起了但网络不保持 -> 查 Nm / CanNm / NM PDU / PNC / CarWakeUp。

PN / PNC 配置与开关联动

CANNM_PN_SUPPORTED / CanNmPnSupported(EB)；PnEnabled / CanNmPnEnabled(EB)
打开: 启用 PN 信息过滤、EIRA/ERA、PN 唤醒相关行为。
关闭: PNC disabled，PN offset/length/mask 不生效。
CanNmCarWakeUpRxEnabled / CanNmCarWakeUpRxEnabled(EB)
打开:
    解析 NM PDU 的 Car WakeUp bit 并上报。
关闭:
    不解析 Car WakeUp。
9.6 COMM_SYNCHRONOUS_WAKE_UP / ComMSynchronousWakeUp(EB)
当前: true
含义: 同步唤醒相关通道。

影响：

多COMM通道项目中，一个通道唤醒可能带动相关通道一起进入通信准备

注意：

客户说“为什么这个通道被一起带起来”，要查 SynchronousWakeUp、PNC、BswM rules、Channel mapping。
9.9 NoWakeup / ComMNoWakeup(EB)
当前:  false
含义:  如果 true，禁止通过该通道唤醒通信。

影响：

请求 FullCom 不一定能把通道从低功耗拉起来。

相关接口：

ComM_PreventWakeUp(Channel, TRUE/FALSE)


ComM_GetInhibitionStatus(Channel, &status)
9.10 Mode Limitation 和 Wakeup Inhibition
Mode Limitation：
作用:  允许运行时限制某通道或整个 ECU 到 NoCom。
接口:
    ComM_LimitChannelToNoComMode(Channel, TRUE/FALSE)
    ComM_LimitECUToNoComMode(TRUE/FALSE)
Wakeup Inhibition：
作用:  允许运行时阻止某通道唤醒。
接口:
     ComM_PreventWakeUp(Channel, TRUE/FALSE)
FullCom 请求失败时，不要只看 CanSM。 查：
    User 请求是否存在
    User 是否映射到 Channel
    ComM_CommunicationAllowed和CommunicationAllowed     gate(API) 是否为 TRUE
    NoCom / NoWakeup 是否置位
    PreventWakeUp 是否置位
    LimitChannelToNoCom / LimitECUToNoCom 是否置位
    DCM 是否 ActiveDiagnostic
9.11 ComMPncSupport / ComMPncEnabled
当前:  false / false
含义:  当前 ComM 不处理 PNC。
打开后：ComM 要处理 PNC ID、PNC 与 Channel/User 映射、EIRA/ERA 信号。
联动模块：
ComM:
    COMM_PNC_SUPPORT / ComMPncSupport(EB) 
    PncEnabled / ComMPncEnabled(EB)
    Pnc / ComMPnc(EB)
    PncId / ComMPncId(EB)
    PNC-channel-user mapping
    EIRA / ERA ComSignal
CanNm:
    CANNM_PN_SUPPORTED / CanNmPnSupported(EB)
    PnEnabled / CanNmPnEnabled(EB)
    PnInfoOffset / PnInfoLength
    PnFilterMask
CanIf:
    CANIF_PUBLIC_PN_SUPPORT / CanIfPublicPnSupport(EB)
CanSM:
    CANSM_PNSUPPORT / CanSMPNSupport(EB)
    CANSM_PARTIALNETWORKING / CanSMActivatePN(EB)
Com / PduR / BswM:
    EIRA / ERA / routing / rules
结论：
PNC 不是只开 ComM 一个勾。 任何一层没配全，都可能导致 PN 唤醒、PN 保持、PN 释放不符合预期。
10.7 CanSM PN 配置

当前：

CANSM_PNSUPPORT / CanSMPNSupport(EB) = false
CANSM_PARTIALNETWORKING / CanSMActivatePN(EB) = false

含义：CanSM 当前不参与 PN 唤醒链路。

如果客户要求 PNC / Selective Wake：

不能只打开 CANSM_PARTIALNETWORKING / CanSMActivatePN(EB)
还要同步检查：
    COMM_PNC_SUPPORT / ComMPncSupport(EB) / PncEnabled / ComMPncEnabled(EB)
    CANNM_PN_SUPPORTED / CanNmPnSupported(EB)；PnEnabled / CanNmPnEnabled(EB)
    CANIF_PUBLIC_PN_SUPPORT / CanIfPublicPnSupport(EB)
    Com/PduR EIRA/ERA
    BswM rules
    CanTrcv selective wake 能力
