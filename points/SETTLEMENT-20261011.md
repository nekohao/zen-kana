## 基线与维护

- `sql-backup/online-confirmed.json`：用户在 2026-10-11 提供的线上结构原件，包含导出范围内全部对象。
- `sql-backup/current-schema.json`：线上原件叠加已审阅、本地待部署修改后的目标结构。
- `schema-full.sql`：目标结构的完整应用 SQL，含表、序列、函数完整定义、约束、索引、触发器、RLS、权限与默认权限。
- `sql-backup/state.json`：记录线上确认时间、已应用与未确认部署的增量脚本。用户确认执行后，把文件从 pending 移到 applied 并更新确认时间，继续保留覆盖层；无需再全量导出，也不会因重新生成而回退。
- `AGENTS.md`：后续修改必须同步基线并一起提交的目录维护约定。

生成：`python points/build-sql-backup.py`。生成器每次最多写 200 行。当前支持已审阅的完整函数替换；新增表、字段、权限等变更须先扩展生成器。生成后核对目标 JSON 和完整 SQL，再提交对应增量。

完整 SQL 是结构与逻辑基线，日常升级执行增量文件。它不是整库数据备份：不包含业务记录、密钥配置行、序列当前值、Supabase 平台结构、扩展安装与 cron 任务。导出中包含其他 public 应用对象，保留供完整核对，不在此次增量中修改它们。恢复到空项目需先准备 Supabase 平台依赖、角色与扩展，并恢复配置/数据。
