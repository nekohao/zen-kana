# 当前产品与交互规则

本文件只描述当前有效规则；数据库函数是结算与权限的执行依据。规则变化更新本文件，不新增日期版本说明。

## 小世界

分数、大转盘、减脂沿用统一圆形主体、切换栏、按钮、总览与弹窗体系；分别使用粉色、金色和绿色主题。小家庭米白色样式限定在家庭页面和家庭弹窗，不覆盖小世界。展示调整不能修改积分、概率、结算算法或身份权限。

小世界与小家庭共用顶部品牌、通知和设置按钮的尺寸与对齐，底部导航外观固定。设置、登录、版本信息和通知中心使用固定公共主题，切换页面或分数、转盘、减脂时不改变外观；家庭任务和菜谱弹窗保留家庭主题。主页面切换轻量淡入，减少动态效果设置下取消动画。

## 小家庭

做饭和其他家务共用一个任务列表。哥哥发起请求后，宝宝完成并提交；宝宝也可以自主登记已完成的做饭或家务。哥哥验收选择合格或不合格，文字评价可选。

合格自动结算任务固定分值一次；不合格不扣分，宝宝返工后重新提交，再由哥哥验收。保留每次提交与评价记录。任务状态和操作版本由服务端校验，重复请求不重复结算。

哥哥在设置编辑分值，宝宝查看最新分值表。任务保存发起时分值，改表不改变既有任务。默认仅洗碗 1 分，其余未确认分值待配置，不捏造正式分数。菜谱和选菜保留；旧未完成餐次进入家庭流程并保留，原点菜模块历史及入口清理，已产生的积分与积分流水保留。新任务不使用五星评分或早中晚餐次拆分。

宝宝自主登记的家事在待验收或返工阶段可撤回，撤回后不展示任务、过程或通知记录，积分不变。已经结算、哥哥发起及旧餐次迁入的任务不能由宝宝撤回。内部仅保留防止网络重试恢复已撤回任务的最少操作标识。

小世界和小家庭顶部设置按钮旁提供通知中心，点击弹窗只显示当前角色需要处理的家事、提现及服务待办，支持分页。读取通知不移除待办，业务处理完成后自动移除；点击进入对应任务、兑现确认或服务处理窗口。历史留在各模块，原有新动态红点保留。

做饭选菜使用独立图片窗口，手机每页四道菜、两列两行，支持分类、搜索、左右翻页；查看做法与选择分开操作，返回保留浏览位置。已选菜单可集中查看、移除，并在表单与任务详情展示缩略图。

记录默认按北京时间今天展示，支持前后一天与弹窗选择日期，日期格式为 YYYY.MM.DD 周几。按任务的家事日期归档当天全部状态，之后提交或验收不改变归属日期。日期接口未升级时，完整读取旧接口的两类分页后筛选，不能只筛最近三十条。

## 减脂与奖励

体重按排便状态分类；界面支持公斤/斤换算。游客不读取管理员的绝对体重或起始体重。管理员起始体重按主动点击查看，取消、关闭与身份失效后清理私有输入。

管理员首页保留记录体重与钻石商城，游客处理服务请求。减脂总览展示体重变化与结算记录；商城展示商品、背包与服务，预计结算不是已到账余额。

钻石每周日北京时间 12:00 结算。首周需记录至少 3 个不同日期并设置起始体重；后续比较周各至少记录 3 天。截止前记录参与均重，同日取最早记录，不补漏记。按原数据库规则奖扣，余额最低为 0，保留计算奖扣与实际奖扣。已结算周期冻结基准与结果，不因后续补删记录或改起始体重重算。

兑换消耗钻石并增加背包；使用背包才发起服务。宝宝确认已服务后，哥哥确认完成或退回背包。退回恢复背包次数，不再次扣钻石或退款。旧请求与操作记录保留。

## SQL 与配置

现有数据库升级执行 ../schema-increment.sql；完整结构核对或准备好平台依赖的新环境恢复使用 ../schema-full.sql。全量不是可在已有数据库任意重复执行的升级脚本。两者始终随数据库代码维护，不代表线上已执行。

新环境的 Supabase 平台角色、扩展、业务数据、密钥配置与调度任务需另外核对，不能把结构基线当作整库备份。
