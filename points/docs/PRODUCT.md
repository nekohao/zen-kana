# 当前产品与交互规则

本文件只描述当前有效规则；数据库函数是结算与权限的执行依据。规则变化更新本文件，不新增日期版本说明。

## 小世界

分数、大转盘、减脂沿用统一圆形主体、切换栏、按钮、总览与弹窗体系；分别使用粉色、金色和绿色主题。小家庭米白色样式限定在家庭页面和家庭弹窗，不覆盖小世界。展示调整不能修改积分、概率、结算算法或身份权限。

小世界与小家庭共用顶部品牌、通知和设置按钮的尺寸与对齐，底部导航外观固定。设置、登录、版本信息和通知中心使用固定公共主题，切换页面或分数、转盘、减脂时不改变外观；家庭任务弹窗保留家庭主题。主页面切换轻量淡入，减少动态效果设置下取消动画。

小世界保留分数、大转盘和减脂切换栏；小家庭直接展示家事列表，不显示模块切换按钮或预留空位。

## 小家庭

做饭和其他家务共用一个任务列表。哥哥发起请求后，宝宝完成并提交；宝宝也可以自主登记已完成的做饭或家务。哥哥验收选择合格或不合格，文字评价可选。

合格自动结算任务固定分值一次；不合格不扣分，宝宝返工后重新提交，再由哥哥验收。保留每次提交与评价记录。任务状态和操作版本由服务端校验，重复请求不重复结算。

哥哥在设置编辑分值，宝宝查看最新分值表。任务保存发起时分值，改表不改变既有任务。默认仅洗碗 1 分，其余未确认分值待配置，不捏造正式分数。菜谱、选菜、食材做法和菜图已移除，做饭作为普通家务用文字说明；旧未完成餐次进入家庭流程并保留，原点菜模块历史及入口清理，已产生的积分与积分流水保留。新任务不使用五星评分或早中晚餐次拆分。

宝宝自主登记的家事在待验收或返工阶段可撤回，撤回后不展示任务、过程或通知记录，积分不变。已经结算、哥哥发起及旧餐次迁入的任务不能由宝宝撤回。内部仅保留防止网络重试恢复已撤回任务的最少操作标识。

小世界和小家庭顶部设置按钮旁提供通知中心，点击弹窗只显示当前角色需要处理的家事和提现待办，支持分页。读取通知不移除待办，业务处理完成后自动移除；点击进入对应任务或兑现确认窗口。历史留在各模块，原有新动态红点保留。

历史家事只保留原菜名与要求，清除菜图、食材、步骤和做法快照。新任务不再选择菜品，数据库拒绝新菜谱内容。

进入小家庭、重复点击底部小家庭导航、回到前台、恢复网络和业务操作后同步。刷新期间保留列表与滚动位置，连续点击合并请求，失败保留当前内容并提示重试。分值表统一从设置进入，不新增刷新或模块切换按钮。

小家庭主页面直接按日期展示家事，移除总览按钮和家庭记录弹窗。顶部标题、进行中数量和日期切换固定，只有中间的家事列表上下滚动；底部主按钮固定，哥哥为发起家事，宝宝为我做完了。

默认按北京时间今天展示，左右切换前后一天，中间按钮今天显示今天，历史日期显示月日并可点击回今天；今天之后不可前进。历史日期同时显示完整日期标题。底部主按钮向右滑看前一天，向左滑看后一天；轻点仍打开发起或登记表单。滑动松手不触发表单，竖向或不足距离的拖动不切日。列表包含所选日期全部状态，完整读取分页，进行中数量只统计待完成、待验收和需返工，不计已完成或已取消。已取消记录不再提示可获分数。

按任务的家事日期归档，跨天提交或验收后仍属于原日期；过去未完成的家事可从日期列表或顶部待办进入处理。从历史日期新发起或自主登记的任务仍归今天，保存后回到今天。详情返回保留日期和列表滚动，切换日期回到列表顶部。加载、空日期和失败状态区分，迟到响应不能覆盖新选择；旧日期接口未升级时完整读取原接口的两类分页后筛选，不能只筛最近三十条。

## 减脂

首页显示最近一次体重相对起始体重、上个完整自然周参考体重的差值。总览展示包含本周的近四周最低体重折线，每个点标注相对起始体重和前一周参考体重的差值。记录页按北京时间倒序分组，保留每天的各次称重。

北京时间周一到周日为一周。每天取最轻的一笔有效记录，每周至少有三个不同日期的记录才计算均重。比较时，上周满三天用均重，有记录但不足三天用该周最低体重，首页注明未算均重。上周无记录时不显示比较数字。趋势每周有一笔就显示最低值，只有无记录的周才断线。新记录统一录入体重，历史已排便和未标注记录合并使用。

界面支持公斤/斤换算。游客仅能读取变化量。管理员起始体重按主动点击查看，取消、关闭与身份失效后清理私有输入。钻石商城、背包、结算与服务流程已移除。

设置中的已验证设备列表再次点击可收起，重新打开设置默认收起。仅显示仍有效的设备名称及北京时间接入时间，不插入最近动态或列表内操作。展开、收起、加载和请求失败不重置设置滚动位置；设置窗口保留稳定的滚动容器，内容变化不模拟全局窗口缩放。设备授权、验证码和服务端撤销能力保持原规则。

## SQL 与配置

现有数据库执行 ../schema-increment.sql 中注明基线后的本次差异；每次新数据库改动清空上次增量再生成。../schema-full.sql 始终保留最新完整结构与逻辑，用于核对或准备好平台依赖的新环境恢复。两个 SQL 同批提交、一起 push，不代表线上已执行；全量不在已有数据库重复执行。

新环境的 Supabase 平台角色、扩展、业务数据、密钥配置与调度任务需另外核对，不能把结构基线当作整库备份。
