# points 长期维护规则

## 授权与范围

- 遵守根 AGENTS.md 的授权边界和每批 200 行限制。开始前核对已有改动；只修改本次涉及文件。
- 目录、文档和展示整理不能顺带修改权限、积分、概率、结算算法或其他模块逻辑。小世界三模块保持统一视觉，小家庭样式必须限定作用域。

## 目录和文档

- 根目录仅保留 README.md、AGENTS.md、.gitignore、两个 SQL 及 index.html、sw.js、version.json、manifest.webmanifest 四个发布入口。
- 运行源码放 src/，工具放 scripts/，回归测试与唯一维护预览放 tests/；资源分别放 assets/、images/、ICON/、vendor/，结构数据放 sql-backup/。
- 文档仅维护 README.md 导航、AGENTS.md 规则、docs/DEVELOPMENT.md 开发发布、docs/PRODUCT.md 当前产品规则。vendor 保留自身依赖说明。
- 不新增日期版本报告、重复模块说明、交付日志或一次性预览副本。变更说明写 Git 提交，过期规则删除；需要历史时查 Git。
- 新文件必须有明确用途，放对应目录并更新导航；不能用改后缀或新增目录来绕过入库检查。

## 可入库与本地材料

- 可入库：必要源码、维护工具、当前文档、两个 SQL、必要图片和固定依赖、可复现回归测试及其夹具。
- 不入库：截图、压缩包、日志、缓存、下载副本、临时 HTML、日期报告、密钥和本地配置。忽略文件留在本地，不为清理仓库擅自删除用户电脑上的其他文件。
- 测试夹具只包含本地虚构身份与必要历史定义，不能混入真实业务数据或密钥。保留测试依赖，使提交后的仓库可以独立复现验证。
- 必须先阅读 git diff 和暂存清单，再逐项暂存本次文件。禁止 git add .、git add -A、目录通配符全量暂存，不夹带其他工作。

## 发布资源

- 改源码后构建，不手工改产物，不复用版本号。纯目录迁移验证使用原版本与时间复现，要求生成内容完全一致。
- 只提交当前 version.json 引用的全部产物与 retained-releases.json 登记的兼容资源。新哈希文件被忽略，需要按清单明确逐项 git add -f。
- 构建仅登记已提交版本，不登记连续试构建副本。保留最近两个旧版本及最近 30 天发布版本；超期文件先审查兼容再删除，不无限累积、不随意清空旧资源。
- SDK 版本、许可和校验信息保留在 vendor/；未经需要不引入新运行依赖。

## SQL 两个固定入口

- schema-full.sql 始终代表最新完整结构与逻辑；schema-increment.sql 只包含本次数据库改动，不是从最早导出累计升级的脚本。不得新增日期或模块命名 SQL。
- 每次有新的数据库改动，先清空上次增量内容，再写本次需要执行的 SQL；完整 SQL、当前结构数据同时更新。纯前端修改不生成新增量。
- 在 current-schema.json 的 increment 中明确本次起始 Git 提交和必要数据迁移；以改动前的维护版本为基线，不默认使用 online-confirmed.json。缺少前置版本时单独说明，禁止为了兼容旧版本把历史升级重新塞入本次增量。
- 使用 python points/scripts/build-sql-backup.py 同时生成两个 SQL；--check 必须检查全量和本次差异都与结构数据一致，拒绝无关历史定义。表结构等新类型变更需扩展差异渲染器，不退回累计脚本。
- 两个 SQL 必须在同一次提交一起 push；提交检查验证成对更新，交付时给出本次增量内容及基线。完整结构未变时，全量头部同步本次增量指纹，不伪造结构变化。
- 历史升级只从 Git 历史读取用于回归，不复制为第三个 SQL，不为让旧测试通过扩大交付增量。全量不用于已有数据库重复升级，不维护 pending/applied 部署状态。
- online-confirmed.json 保留原始只读参考，不伪装成已部署最新版，不用旧导出覆盖当前维护基线。
- 历史定义集中在 tests/database-fixtures.json，只有测试与只读导出使用；不把它作为第三份部署 SQL，不运行已过期通知构建或密钥工具。
- 结构基线不含业务数据、密钥配置、平台安装或调度配置；仅外部改库或需核实线上差异时索取新导出。

## 提交检查

- 提交前执行 node points/scripts/check-repo.mjs --staged、SQL --check、资源验证和本次相关回归。仓库检查只能发现命名与范围错误，仍需审阅实际差异。
- points/scripts/hooks/pre-commit 在本地阻止不合规暂存；GitHub 检查复核已提交树。不得为了提交绕过钩子或把不明文件加入允许清单。
- 构建成功、Git 推送和线上数据库执行是独立结果；没有执行或确认的动作不能宣称已完成。
