# points 稳定性检查与修复（2026-10-06）

回退基准：`372d240`。本次调整启动与交互可靠性，未改变积分、转盘概率、减脂统计或钻石结算规则；未修改线上数据库。

## 已复现的故障

1. **启动依赖卡住，页面所有按钮不响应。** 原页面在绑定交互之前同步加载外部 CDN SDK。模拟该请求不返回时，页面停在 `readyState=loading`，减脂入口没有生成，设置点击无效。当前 SDK 改为同站点的固定文件，并在依赖失败或 8 秒未完成初始化时提供重新加载入口。
2. **快速切换回减脂被忽略。** 原切换动画会先更新选中状态、155 毫秒后才更新实际模块状态。快速切回原模块时，旧的“已经选中”判断会忽略点击，随后旧定时器覆盖界面。已允许新点击取消并替换待完成切换。

## 其他已修复因素

| 风险 | 当前处理 |
| --- | --- |
| 请求一直不返回，按钮/弹窗长期忙碌 | RPC 和会话操作 15 秒上限，浏览器请求可中止；身份锁获取上限 10 秒，保持原有锁机制 |
| 减脂同步拖住积分刷新 | 减脂读取与基础读取分开启动，失败不会拖住其他模块 |
| 一项基础请求失败丢弃另一项成功数据 | 积分与转盘分别接受成功数据，失败后保留已有显示 |
| 商城打开前等待多项请求 | 先打开现有界面再并行同步；用户关闭后，迟到请求不会重开窗口 |
| 转盘、积分和其他操作连点 | 操作处理中拒绝同一操作再次进入；转盘从请求开始保护，到处理完成释放 |
| 响应丢失被误认为没有提交成功 | 显示结果待确认；关闭 SDK RPC 自动重放；钻石购买/使用继续保留原幂等操作 ID |
| 身份变化或写入之后，旧读取覆盖界面 | 以身份和读版本检查返回结果，丢弃已经被新状态替代的请求 |
| 起始体重读取失败后输入一直禁用 | 失败后释放输入和保存控件；仍由原管理员权限和服务端校验控制保存 |
| 模块初始化失败不提示 | 提供重新加载提示；钻石模块失败与基础减脂隔离 |
| 后台暂停动画或动画未结束 | 为等待动画完成设上限，结束在已经收到的服务端结果 |
| 恢复网络、返回页面不同步 | online/pageshow/visibility 恢复时刷新并合并重复恢复请求 |
| 版本更新打断未完成操作 | 弹窗打开或操作忙碌时提示新版本，交由用户完成后重新加载 |
| 非法日期、不可用画布导致异常 | 日期显示回退文本，画布无尺寸或无绘图上下文时跳过绘制 |

## SDK 与隐私核查

本地 SDK 为原浮动 CDN 当前分发的 2.117.2，MIT 许可证随文件保存。验证 npm 包 SHA-512 完整性、UMD 文件与固定 CDN 版本字节一致，SHA-256 记录在 vendor/README.md。

隔离测试中的 SDK 初始化、会话读取和 RPC 只访问配置的服务地址，没有观察到额外上传目的地。本次未增加遥测、私人数据缓存、管理员密码或服务密钥。测试拦截了业务请求，未访问真实数据库。

奖励 SQL 在仓库中启用 RLS、撤销表直接访问、限制内部函数调用，并在管理员写入函数中再次检查权限。游客接口返回受控快照，管理员快照不返回实际体重。

**范围限制：**原积分和体重函数、线上 RLS/授权、数据库部署状态不完整地存在于仓库，无法仅凭这些文件确认线上隐私配置。现有无需登录的游客设计允许游客读取其公开界面，并执行相应游客操作；SDK 本地化没有改变这些权限。

## 验证

`stability.test.mjs` 使用本地模拟状态，外部业务请求全部拦截。23 项断言覆盖启动、快速切换、超时解锁、恢复、缺失模块、真实固定 SDK 兼容、连点、退出身份、异常日期与未知兑换结果；组合断言另外检查读取合并、身份/写入后丢弃旧结果、会话超时、取消信号。

运行：`node points/stability.test.mjs <playwright/index.mjs> <Chrome可执行文件>`。

本次浏览器验证基于 Windows Chrome，并不等同于真实 iPhone Safari/PWA 长时间运行验证。未修改数据库逻辑，因此未重复数据库迁移测试。

## 商业化前仍需验证

- 在真实手机和 PWA 中覆盖首次安装、弱网启动、长期后台恢复和持续使用；本地模拟不能保证浏览器/系统永不崩溃。
- 核对线上原有接口权限和事务逻辑。原积分、提现、正式抽奖等接口的数据库定义缺失，不能确认它们在跨设备及刷新后的重试中具有幂等保障。前端防连点不能代替数据库幂等键。
- 总览仍一次读取最多 10000 条记录，长时间运营后应改为服务端聚合和游标分页，并以真实数据量做性能测试。
- 需要真实环境的备份恢复验证和可去除私人数据的错误监测，才能进一步确认长期运行可靠性。

参考：[Supabase 客户端初始化](https://supabase.com/docs/reference/javascript/initializing)、[身份变化回调](https://supabase.com/docs/reference/javascript/auth-onauthstatechange)。身份回调中的后续校验仍在回调结束后执行。

## iPhone 主屏幕启动恢复补充（2026-10-06）

用户反馈第一版仍持续显示加载未完成，需要关闭后台才恢复。第一版的 8 秒提示只暴露了问题：同站点脚本依旧同步阻塞初始化，重新导航仍可能沿用未完成的资源加载。

第二版移除同步外部脚本/样式标签，通过同站点 fetch 下载，10 秒超时后中止请求。失败前尚未执行核心业务代码时，用户点击「重试启动」在原页面取消旧请求、对未成功的资源重新获取，成功下载的源码在当前页面内复用。启动失败后最多自动重试一次，避免无限循环。

启动过程进入后台时取消未完成的加载；恢复前台或恢复网络后重新尝试。核心代码只允许执行一次；完成启动后的前后台切换继续沿用数据同步，不重复创建客户端、绑定事件或重放写入。

核心业务脚本从 index.html 迁移至 app.js，比较确认仅清理文件末尾空白，业务代码一致；文件分 9 批、每批不超过 500 行写入。发布时须同步包含 app.js；仅发布新的 HTML 而遗漏该文件会显示启动失败。

版本检查不再自动替换整个 WebView；读取到相同构建号时记录当前版本，不触发二次导航。不同构建号仅在界面启动完成后提示用户更新。后续发布应同步修改 HTML 的 points-build 与启动器 BUILD，确保资源缓存版本一致。

当前共 35 项本地断言通过。新增验证了手动原地重试、后台中断后恢复、连续恢复不重复初始化、不重复提交、样式资源卡住不阻塞 HTML、错误 HTML 缓存响应可被替换，以及版本检查不会打断启动恢复。验证使用隔离的 Chrome 与合成生命周期事件，仍须在真实 iPhone 主屏幕 App 中确认实际系统行为。

启动阶段可在本机调试时读取 PointsStartup.status()，只包含阶段、尝试次数和资源标签，不含账号、体重或令牌，也不上传。

机制依据：[DOMContentLoaded 与脚本/样式等待](https://developer.mozilla.org/en-US/docs/Web/API/Document/DOMContentLoaded_event)、[AbortController.abort](https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort)、[pageshow 生命周期](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event)。

## 起始体重按点击查看（2026-10-06）

管理员设置页固定显示「点击查看」，打开设置、身份校验及切换单位不读取或显示起始体重。只有点击该项才调用原有管理员读取接口，在弹窗内以当前单位显示已保存的数值。

弹窗先提供「修改」和「取消」；选择修改后才允许编辑，再选择保存修改才写入原有接口。取消返回设置，不写入；取消、保存或身份失效均清空私人体重输入。迟到的读取响应不能重新填入已关闭的窗口。读取失败时只能重试读取或取消。

构建号更新至 20261006.3。当前 60 项本地检查通过，包含上述查看、取消、编辑保存、单位换算、失败重试、迟到响应和游客权限检查；测试使用模拟数据，未修改线上数据库。
